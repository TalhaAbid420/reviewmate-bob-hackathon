Overview

This PR introduces a three-endpoint REST API (POST /tasks, GET /tasks/:id, DELETE /tasks/:id) backed by an in-memory store — a self-contained change that establishes the core task-management surface of the service.

As written, the API ships with no authentication layer and no input validation, meaning any unauthenticated caller can freely create or destroy all data, and malformed payloads reach the store unchecked — both are showstopper gaps for a service exposed beyond localhost.

Top 3 Findings — Ranked by Severity

#1 — No authentication or authorisation on any endpoint High
app.js:6  /  routes/tasks.js:4  ·  Category: Security
All three endpoints are mounted without any authentication middleware — any unauthenticated caller can create or delete every task in the store. This is a complete BOLA (Broken Object Level Authorization) exposure. No amount of input validation fixes this; an auth middleware (JWT, session, or API key) must be added as a prerequisite to deployment.
#2 — Missing input validation on POST /tasks High
routes/tasks.js:10–11  ·  Category: Security + Correctness
title is taken verbatim from req.body and written to the store with no type check, presence check, or length limit. An attacker (or a bug) can store null, an object, an array, or an arbitrarily large string — opening vectors for data corruption, prototype-pollution downstream, and memory-exhaustion DoS. The source comment acknowledges this is a known gap, making it an explicit merge blocker. A single guard (if (!title || typeof title !== 'string')) resolves it.
#3 — DELETE /tasks/:id has zero test coverage Medium
routes/tasks.js:26–32  /  tests/tasks.test.js  ·  Category: Test Coverage
The only destructive endpoint in the API — the one most likely to cause data loss — has no tests at all. Neither the happy path (204 + resource removed) nor the error path (404 on missing ID) is asserted. Any regression or future security bug in the delete path will pass CI undetected. Four lines of test code cover both branches; there is no reason this shipped untested.

Required Changes Before Approval

  • Security Add authentication middleware to app.js before mounting /tasks — JWT, session, or API key at minimum.
  • Security Add input validation guard in POST /tasks: reject missing, non-string, or empty title with 400.
  • Tests Add tests for DELETE /:id: happy path (204 + subsequent GET returns 404) and not-found path (404 + error body).
  • Security Set a body size limit on express.json() in app.js: express.json({ limit: '10kb' }).
  • Security Validate req.params.id is a positive integer before forwarding to the data layer (GET and DELETE).

Recommended Follow-ups (Non-blocking)

  • Quality Extract the duplicated { error: 'Task not found' } literal into a shared helper — single point of change.
  • Quality Hoist the Number(id) coercion in db.js into a shared toId() function used by both getTaskById and deleteTaskById.
  • Quality Add GET /tasks (list all) — the absence of a list route is an asymmetry that will surprise API consumers and is a one-liner to add.
  • Tests Add edge-case tests for POST /tasks with missing/empty/non-string title to document (and gate) the currently silent acceptance of bad data.
  • Quality Wrap module-level mutable state in db.js in a factory function to improve testability and avoid shared-singleton side-effects.
